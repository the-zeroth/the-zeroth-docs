A **Plugin** packages capabilities that Agents can use (Skills, scripts, MCP servers, apps and connections to online services) so that you can install, configure, share and give them to a role as one unit. Plugins are the only kind of extension in The One, and the apps some of them bring open from **Apps**.

## What a Plugin contains

A Plugin combines any number of five kinds of components:

| Component | What it adds |
| --- | --- |
| Skill | Written know-how that a role reads when it needs it |
| Script | A program the Plugin runs as a tool for an Agent |
| MCP | An MCP server and its tools |
| Application | An app with its own screen, opened from Apps |
| Connector | An online service the Plugin reaches with your API key or sign-in |

Plugins live outside every Definition Space. They are installed on your computer, and a Space records only which Plugins its roles use and their settings that are not secret. That is why an exported or shared Space never contains a Plugin, only references to the ones it needs. For what lives in a Space and what lives on this computer, see [Definition Spaces](./definition-spaces).

## The Plugin library

Open **Teams and tools › Plugins**. Plugins and Definition Spaces share one page, titled **Extension Center**, and Plugins has two views:

- **Plugin library**: official Plugins and Plugins others have shared. Each row shows the version and what the Plugin does; open one to see its components, the access it declares and its settings.
- **Installed**: the Plugins on this computer, including the ones you made, with **Update** when the library has a newer release.

When a Plugin has several releases, its details let you pick the **Version**: the list marks the one **Recommended for this device** and the **Latest**, and a release with no package for this computer is marked **Unsupported on this device**.

## Install a Plugin

Installing puts the Plugin on this computer, whichever Space is active. It is used once you give it to a role in a Space of your own (below).

1. Choose **Install Plugin** on its row.
2. **Review Plugin change plan** lists what will be installed, the permissions it asks for, and any settings it needs before it can run.
3. Choose **Continue to confirmation**. The One asks you to confirm the changes and permissions in a window of its own, then installs the Plugin in the background.

When a Plugin cannot be installed, it says why: **Unavailable on this platform** means it has no package for this computer's platform, and a Plugin that needs a newer The One asks you in the plan to update The One first.

On the website, **Open in The One** on a Plugin in the [Plugin catalog](https://the-zeroth.com/en/extensions) starts the same from your browser. The app first verifies the signed release, while nothing is installed yet, then asks which Space it goes to; only Spaces of your own can be chosen. Downloading it, approving full local access and writing to the Space are each confirmed separately.

A Plugin needs no Python or Node on your computer. The One builds a Python environment for it from the Plugin's own locked list of packages, and the first build can take a few minutes. Servers written for Node can run on the Node that comes with The One.

## Settings and connections

A Plugin's details hold two kinds of settings:

- **Configure Plugin**: ordinary values such as models and endpoints.
- **Plugin connections**: API tokens, OAuth sign-ins and shared accounts. Signing in opens your browser. Connections are kept on this computer; which one the active Space uses is chosen under **Current Space usage**, in a Space of your own.

Keys and sign-ins are stored encrypted on this computer. They are never part of a Plugin package or a Definition Space. When an Agent needs a key to go on, it can ask you for it with a secure setup card: what you type there goes straight to protected storage, and the Agent only learns whether the connection is ready.

The **Overview** of a Plugin's details has a **Runtime status** line for the active Space: **Ready**, **Action required** or **Unavailable**. A missing setting, or a sign-in or account still to choose, shows there, and it reads **Not used by this Space** when the active Space does not use the Plugin.

## Give a Plugin to a role

Installing a Plugin does not run it. Choose **Add to Agent** in the Plugin's details to add the whole Plugin to a role without opening the role's editor, or pick it under **Plugins** in the editor itself (see [Roles](./roles)). Both work in a Space of your own: the official Space is read-only, so copy it first (see [Definition Spaces](./definition-spaces)). The main assistant can do this too, and it can make Plugins of its own from Skills, scripts and MCP servers.

Many built-in roles already list official Plugins as optional; see "Used in the official Space by" in the table below. In a Space copied from the official one, you do not need to add those Plugins to these roles again once they are installed.

When roles in your Space refer to Plugins you have not installed, for example after you import a Space, **Installed** says **Some Agents still need Plugin setup**. **Review all requirements** makes one change plan for every Plugin the Space's roles need and installs them together once you confirm; or install just the ones you need from the library, and let Plugins for roles you do not use wait.

To remove a Plugin from this computer, use **Uninstall Plugin** in its details. The roles, prompts and templates in your Spaces keep their references to it, and those references resolve to nothing until you install it again.

## Apps

Once a Plugin brings an app you can open, **Apps** shows in the sidebar: it opens a quick menu of the apps your Plugins bring, and Cmd/Ctrl+Shift+A opens it from anywhere in the app. Double-click **Apps**, or choose **Manage all applications**, for the full list; **Teams and tools › Apps** opens it too.

Apps follow the active Space: the list shows the apps of the Plugins that Space uses, and it changes when you switch Spaces.

A click opens an app that can run inside The One, such as OneCanvas, as a tab in the workspace of the **All runs** page. **Other ways to open** lists the others the app supports: in an isolated web window, in the system browser, or as a native application. Closing an app's own window also stops the app.

## What a Plugin can do on your computer

Executable components run with your own user permissions: while they run, they can read and change files, use the network and start programs. What a Plugin declares under **Access and capability disclosures**, and the **Full local access** badge, describe what it expects to do; they are not a sandbox. A publisher's signature (**Verified source**) shows who published a Plugin and that its files have not changed since. It does not certify that the code is safe.

As with every tool, what Agents do through a Plugin is recorded in **Settings › Data and undo › Action log**. See [Action log, undo and stopping](../action-log).

## Make and share a Plugin

In **Installed**, **Create Plugin** opens the Plugin's manifest, a JSON file in which you declare its Skills, scripts, MCP servers, apps and connectors by hand; it also needs a Space of your own. Asking the main assistant to build the Plugin is usually easier.

To share a Plugin you made, choose **Share Plugin**, pick a visibility (**Public**, which is selected at first, listed after review; **Unlisted**, reachable by its link; or **Private**, visible only to your account) and add tags. Sharing needs you signed in to your The Zeroth account, and the visibility and tags apply only to the first share: later versions keep the settings on the website. The One packages, signs, uploads and submits it in one step. The names and descriptions of its settings are shared; your tokens, accounts and the values you entered are not. Follow the review with **Manage on website**.

| --- | --- | --- |

| OneCanvas | An infinite canvas app where you and Agents arrange, annotate and connect things on the same board | Main assistant, General group, Frontend design studio |
| Image Generation | Image prompt design and generation through Image2-compatible, Gemini, OpenRouter or APIFrame accounts | Image studio, Frontend design studio |
| Video Production | Plans and reviews video productions, and runs Seedance video jobs through a Volcengine Ark account | Video studio, Frontend design studio |
| Blender Control | Builds scenes, renders and exports with the Blender installed on your computer | Main assistant, General group, 3D scene studio |
| Gmail Control | Searches, reads, drafts, sends and organizes Gmail after you sign in with Google | Main assistant, General group |
| Mailbox | Sends, reads, searches and sorts mail in a real mailbox over IMAP and SMTP (QQ Mail, NetEase, Gmail, iCloud and others, with the authorization code or app password the provider gives mail apps; Outlook and Microsoft 365 mailboxes are not supported yet); rehearses locally first, where sending reaches nobody | Site launch team, Store operations, Store weekly review, Storefront studio |
| Payments | Takes payments with Creem or Stripe: products, payment links, orders, refunds and revenue; rehearses locally, then in the provider's test mode, before real money moves | Site launch team, Store operations, Store weekly review, Storefront studio |
| Sites | Puts websites online with Cloudflare: publishes a folder, rolls back, attaches domains, sets DNS records and registers domains; rehearses on this computer first | Site launch team, Store operations, Store weekly review, Storefront studio |
| Tavily Search | Lets the built-in web search use your own Tavily account; without it, web search uses your model provider's own | Works once installed with a key; no role needed |
| Agent Room Channel | Lets **Settings › Phone and other programs › Phone channel** reach your Agents from your phone through Agent Room; see [Phone channel and outside callers](../remote) | The Phone channel uses it; no role needed |
