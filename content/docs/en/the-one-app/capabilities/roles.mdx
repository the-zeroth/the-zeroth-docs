A **role** is one Agent of a working group written down: what it does, which model it thinks with, and which prompts, Skills, tools and Plugins it can use. Every node of a working-group template is bound to a role, so one role can serve in several templates, and every Agent that plays it starts from the same definition. See [Working-group templates](./working-group-templates).

Teams and tools and the editor both call them **Roles** (the editor's tab is **Roles**). Open one from **Teams and tools › Roles**, or choose **New role** above the list. The list is grouped in folders, and a role that inherits from another sits indented under its base. **New folder** adds a folder; drag a role into it to move it.

The editor has three tabs: **Configuration**, **Prompts** and **Capabilities**. Each change applies when you save: groups formed afterwards use it, and Agents already at work pick up what you added or changed from their next turn, while a reply already being written finishes as it was. Removals are another matter. Skills and Plugins you remove are gone from Agents at work from their next turn; tools, external tool servers and prompts you remove stay with Agents already at work, and only groups formed afterwards go without them.

## Configuration

### Identity

The **Identity** block holds the name and description, with inheritance below them. The **Name** is the role's ID. Renaming it later also updates the roles that inherit from it and the templates that use it.

The **Description** says what the role is good at. Agents read it too: an Agent that may hand work to this role finds the description in its list of handoff targets, so write it for them.

### Inheritance

Under **Inheritance**, pick another role and this one starts from it. Each part then shows **Inheriting** or **Override**: switch a part to Override to set it here. A family of similar roles can share one base and keep only their differences.

### Model

Under **Model & Parameters** a role gets its model in one of three ways:

- **A model preset.** Pick a saved preset under **Model preset**: model, connection, reasoning and service tier come together. When the preset changes, the role follows from its next turn.
- **Use default model.** The role follows the global default, which you set in **Settings › Models and sign-in › Default model** or from the model menu under the main assistant's composer. The editor shows the **Current default**.
- **Its own settings.** Leave both off and set **Model connection**, **Speed / service tier**, **Model** and **Reasoning (thinking)** here.

How a role's own model ranks against a model chosen for one run, the template's default and the global default is explained in [Models](./models#which-model-wins).

**Composition & sources** sums up what the role is made of and where each part comes from: its own settings, or the role it inherits from. Select a line to jump to that part.

## Prompts

- **Structured Prompt** mounts prompts from **Teams and tools › Prompts**. Select one to preview it; **Edit** opens it in the prompt editor. Several small prompts combine better than one large one, and a prompt mounted by many roles is changed in one place. Every role in the official Space mounts the shared prompt `Agents' cognition`, for example.
- **Extra Prompt** is a short prompt for this role alone.

An Agent reads the role's own prompt (its Extra Prompt) first, then its mounted prompts, then any text its template adds for that node. See [Skills and prompts](./skills-and-prompts).

## Capabilities

What a role can do is what you give it here. Nothing asks for approval when it uses what it has: every call is recorded in **Settings › Data and undo › Action log**, and changes to files can be undone there. See [Action log, undo and stopping](../action-log).

### Plugins

Choose the Plugins this role can use. A Plugin goes in whole, with its Skills, scripts, external tools, apps and connections: **Add whole Plugin** adds it, and **Advanced component settings** picks single components when you need to. A Plugin marked **Required** has to be installed for the role to run. **Open Plugin Center** installs Plugins and manages their connections.

You can also start from the other side: **Add to Agent** in the Plugin library adds a Plugin to the role you pick. See [Plugins and Apps](./plugins).

### Tools

**Tools** are the built-in toolsets: reading and writing files, running commands, the web, talking to you, handing tasks out on a TaskBoard, starting sub-Graphs, memory and more. Expand one to see its **Exposed Functions** and switch single functions off, fill in its **Instance Config**, give it another name for the model to see, or add a usage constraint to its description.

Tools marked **Full local access** act with your user account's rights on files, the network and processes. The marking discloses what the tool can do; it does not limit it.

### Skills

**All** gives the role every Skill in the Space, including Skills added later; **Custom** picks them one by one. A Skill sits in the Agent's context as a short card and is opened only when the work calls for it, so a long list costs little.

### MCP Servers

**All** enables every external tool server in the Space, including servers added later, which reach the Agent from its next turn. **Custom** picks servers one by one. The [External tools (MCP)](./mcp) page only defines the connections; this is where a role gets them. A role that inherits takes its servers along with its **Tools**: switch Tools to Override to choose servers of its own.

![The Capabilities tab of a team role](/docs-assets/images/0.5/en/roles-capabilities.png)

In the official Space, the main assistant and the General group's assistant get every built-in tool, Skill and server, while team roles get only what their job needs. The software team's solution lead, for example, has files, commands, the web, a TaskBoard, the graph tools and the Chrome DevTools server.

## Source, the built-in roles and the official Space

- **Source** shows the role's file as it is saved, read-only, with its path in the Space. **Delete** at the bottom of the editor deletes the role.
- The built-in roles (`main-assistant`, `chat-assistant`, `atlas-director`, `nightly-reviewer` and the evolution lab's three) are listed like any other and can be edited in your own Space. The main assistant is the conversation everything reaches, so change it with care.
- In the official Space the editor is read-only. **Duplicate to edit**, in the notice at the top, copies the Space and switches to the copy. For what else can change there, see [What you can change in the official Space](../capabilities#what-you-can-change-in-the-official-space).

You do not have to edit roles by hand: the main assistant, **The Director** bar on the Atlas canvas and the evolution lab change them too. See [Who changes them](../capabilities#who-changes-them). A role, together with its template and the other members, makes up the gene of a reusable working group: see [A-Genetic Engineering](../../multi-agent-architecture/a-genetic-engineering).
