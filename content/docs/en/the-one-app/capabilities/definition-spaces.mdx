A **Space** is one complete set of what your Agents work with: working-group templates, roles, prompts, Skills, external tools (MCP), scripts, request templates, a models file naming the models it was tuned for, and the Space's memory, together with the list of Plugins its roles use. You can keep as many Spaces as you like, for example one per client or kind of work, and they do not affect each other.

Manage them on the **Spaces** page. The Space switcher at the top of the sidebar, beside **The One**, shows the active Space; pick another from its menu to switch. **Manage Spaces…** at the bottom of the menu opens the page, and so does **Manage Spaces** at the top of **Teams and tools**; in the Extension Center it sits beside **Plugins**.

![The Spaces page with the official Space and a copy](/docs-assets/images/0.5/en/definition-spaces-page.png)

## What is in a Space, and what is on this computer

Everything in a Space is a file in the Space's folder:

- working-group templates, roles, prompts, Skills, the settings of external tools (MCP), and scripts;
- request templates, the ones in the composer's **Templates** menu;
- the models it was tuned for: the names and thinking depths of the main model and the slots, without connections or keys (see [Models](./models#a-space-names-its-models));
- the Space's memory (see [Memory and recall](./memory));
- which Plugins its roles use, and those Plugins' settings that are not secret.

Switching Spaces swaps that whole set. Other things belong to the computer and every Space shares them:

- **The model connections, and this computer's main model and slots** (see [Models](./models)). This computer's main model and slots run where the Space names no model, or names one this computer cannot run. Roles and templates bind slots by name, so when you share a Space, its roles run on the other computer's main model and slots; a role that names a saved configuration or a particular connection needs the same one on the other computer.
- **The Plugin library**: the Plugins installed on this computer, the apps they bring, and their settings, connections and keys (see [Plugins and Apps](./plugins)). Every Space uses this one library, and a Space's roles name the Plugins they use.
- **Settings › Data and undo › Action log**, which covers every Space so that undo can reach everything (see [Action log, undo and stopping](../action-log)).
- A few more things span Spaces: the weekly report's spend is the total for every Space; **Pause all** on the triggers pauses every Space's triggers; and what earlier sessions concluded in a project folder can be found from any Space (see [Memory and recall](./memory)).

Where does something new belong? Roles, prompts, templates and request templates belong to a Space. A capability with its own code, dependencies, settings, keys or app screen should be a Plugin, so every Space can use it and it can be updated on its own. A Skill or external tool that only makes sense in one Space can stay in that Space.

## What every Space carries

Every Space carries five built-in templates, with the roles, prompts and Skills they use:

| Template | Called in the app | What it is |
| --- | --- | --- |
| `main_assistant` | **Main assistant** | The [main assistant](../main-assistant) itself. The app keeps one run of it per Space. |
| `chat` | **General group** | One assistant that does ordinary multi-step work with tools directly. |
| `atlas` | **Definitions studio** | Its director writes and changes working-group templates, roles, prompts, Skills, external tools (MCP) and Plugins; the bar at the bottom of [Atlas](./atlas), **The Director**, runs it too. |
| `nightly_review` | **Nightly review** | Started each night at 03:30, only when there is something new to review. |
| `self_evolution_lab` | **Self-improvement lab** | The lab that works on evolution matters, with three roles: the Director, the Patcher and the Verifier. |

For the last two, see [Evolution: the lab and the nightly review](../evolution). Every Space also carries six built-in request templates, such as **Implement a feature**, **Diagnose and fix a problem** and **Create a plugin for The One**, which show in the composer's **Templates** menu.

When you create, duplicate or import a Space, and each time the app starts, The One adds any of these that are missing. Files that are already there are never overwritten, so your changes to them stay; it also means later improvements to these built-ins do not reach the copies you already have, except in a copy that follows the official Space (below). Built-in templates are not in the template list, so Teams and tools shows a card for one only while it works for a matter.

A new, empty Space therefore starts with these five templates and nothing else, and with no external tool (MCP) servers. Until it has templates of its own, the main assistant gives ordinary work to the General group (`chat`).

## The official Space and your own copy

The One comes with the official Space, listed as **Official**. It is read-only: the app refreshes it on every launch, so it always carries the current version's templates, roles and Skills, and nothing else can change it. While you work in it:

- templates, roles, prompts, Skills and external tools (MCP) can be read but not changed;
- the models it names (GPT-6.2 Sol) can be read but not changed either; where this computer can run them, the official Space runs on them (see [Models](./models#a-space-names-its-models));
- what the main assistant and the evolution lab find to improve stays a proposal (see [Evolution: the lab and the nightly review](../evolution));
- Agents cannot write memory.

Plugins and this computer's models are not affected, because they live on this computer: in the official Space you can still install Plugins and change this computer's main model and slots, and a Plugin its roles name works once installed. You just cannot add a Plugin to another role there.

So work in a copy of your own. A new install of The One starts in one, called **My Space**. If you upgraded from an earlier version and are still in the official Space, these places copy it:

- **Copy the official Space and use it** in **Get started**, and **Duplicate to edit** in the notice at the top of the role, prompt and Skill editors, copy it and switch to the copy at once;
- **Duplicate to edit** on the official Space's row of the Spaces page makes the copy; choose **Switch here** to start using it.

You, the main assistant and the evolution lab can change the copy freely.

### Following official updates

A copy of the official Space made in the app, **My Space** included, follows the official Space: select it on the Spaces page and its details are marked **Follows official**, with a **Follows the official Space** section below. After you install a new version of The One, the next start compares each file:

- Files you have not changed take the official version by themselves; files the official Space adds come in, and files it removes go.
- Files you or your Agents changed keep your version, and the official version waits for you to choose. When some wait, the Space menu at the top of the sidebar says how many beside **Manage Spaces…**, such as **Official updates: 2**, and the **Follows the official Space** section lists each file: **See what differs** shows both sides, **Use the official one** takes the official version (**Remove it, as the official Space did** for a file it removed), and **Keep mine** keeps yours.
- Each update is in the Space's change history and can be undone.

**Stop following** asks first; once a copy stops following, later official updates no longer come into it, and it cannot follow again. Spaces copied before 0.5.3, imported Spaces and copies of a copy do not follow the official Space.

Each Space in the list carries a badge: **Current** for the active one, **Read-only** or **Editable** for the others.

## What follows the active Space

Only one Space is active at a time, and the app shows that Space's work:

- the main assistant and its conversation: each Space has its own;
- matters, working groups and what waits for you;
- triggers: another Space's triggers wait until you switch back to it, and then by default catch up once;
- the weekly report and the nightly review;
- the runs in All runs;
- your standing rules: each Space has its own, and the Agents of a Space see only that Space's (see [The main assistant](../main-assistant#your-standing-rules)).

## Switch, create, duplicate and delete

- **Switch here**, or the switcher at the top of the sidebar, changes the active Space at once, without a restart. If Agents are still at work, The One says how many and offers **Stop and switch**: they all stop first, and the step each one is on is cut off, not finished.
- **New Space** starts an empty Space with only what every Space carries (above).
- **Duplicate** copies a Space together with its memory and the standing rules you set for it. A copy of the official Space follows official updates; a copy of any other Space does not.
- **Edit** renames a Space of your own or changes its description.
- **Delete** removes a Space of your own, with all of its definitions, its memory and the standing rules you set for it, for good. The active Space and the official one cannot be deleted.

## Export and import

**Export** packs a Space into a `.zerospace` file. Keys, tokens and passwords in its MCP settings are removed first. **Include agent memory** is on by default; turn it off to leave the memory out. See [Memory and recall](./memory). Your standing rules never go with an export or a share.

**Import** reads a `.zerospace` file and shows what is inside before anything is written: how many roles, prompts, templates, MCP servers and Skills it holds, which scripts its Agents could run after the import, which MCP servers would run a command on your computer or connect elsewhere, and anything that fails validation, which stops the import. When the Space contains scripts or local commands, the button reads **I trust the source. Import**: import only Spaces from sources you trust.

A Space carries references to the Plugins its roles use, never the Plugins themselves. Once you use an imported Space, **Installed** in **Teams and tools › Plugins** lists at the top the Plugins its roles use that this computer cannot run yet, so you can install the ones that run here. See [Plugins and Apps](./plugins).

## Share on the website

**Share to platform** publishes a Space to the sharing platform on the-zeroth.com. Sharing needs you signed in to your account in The One (**Settings › General**).

- **Visibility**: **Private** is chosen for a first share; **Unlisted** makes it reachable by its link, and **Public** lists it for everyone.
- You can add a few tags, separated by commas.
- **Include agent memory** is off by default, so your notes and project context stay on your computer unless you turn it on.
- Keys, tokens and passwords in MCP settings, including those inside addresses and connection strings, are removed before the upload, and the platform refuses a bundle that still contains one.

Sharing the same Space again uploads a new version: the dialog starts from the last visibility and tags, and the visibility you choose this time applies. You need a username, set in the console on the website, before a share link can be made.

To use a Space someone else shared, choose **Browse sharing platform**, find the Space on [the-zeroth.com](https://the-zeroth.com/en/spaces) and choose **Open in The One**. The app downloads it and shows the same preview as an import from a file.
