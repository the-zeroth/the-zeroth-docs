这份记录覆盖 The One 0.4.0 到 0.4.28。

0.3.0 让 Agent 可以在运行时自己扩展能力。0.4.x 则给这些能力一个独立的包：**插件**可以作为一个整体被制作、分享、安装并添加给 Agent，而 Definition Space 只引用它用到的插件，不再复制它们。

## 核心变化

### 插件

插件把 Agent 可以使用的能力打包在一起。一个插件可以任意组合五类组件：Skill、脚本、MCP server、应用，以及连接远程服务的连接器。

- 侧边栏新增**扩展**页面，**插件**与你的定义空间放在一起。你可以浏览**插件库**、查看**已安装**的插件，并且无需打开完整的 Agent 编辑器，就能把整个插件添加给某个 Agent。
- 每个插件都有自己的设置：模型、端点等普通配置，以及用于 API token、OAuth 登录和共享账号的**连接**。Token 与账号登录态永远不会成为插件包或 Definition Space 的一部分。
- 带有应用的插件，可以从新增的**应用**页面打开，应用与 The One 隔离运行。
- Agent 也可以制作插件。`plugin_authoring` 工具让 Agent 把 Skill、脚本和 MCP server 组合成插件、校验它，并把它添加给 Agent。

可执行的插件组件以你本人的用户权限运行：运行时可以读取和修改文件、访问网络并启动进程。插件的签名声明用于说明它预期会做什么，而不是沙箱。安装插件或把它加入 Space，本身不会运行它的代码。

### 插件目录

- 官网的[插件目录](https://the-zeroth.com/zh/extensions)列出已发布的插件。点击**在 The One 中打开**会把插件交给桌面应用：桌面端先验证签名发布，再让你选择 Definition Space 并确认权限。下载、批准完全本地访问、写入 Space，都会分别请你确认。
- 你可以在桌面应用里分享自己制作的插件：选择**分享插件**，设置可见性——公开（审核通过后进入插件库）、不公开列出（仅可通过链接访问）或私有——并添加标签。The One 会一次完成打包、签名、上传和提交。插件设置项的名称与说明会被分享；你的 API token、账号凭据和已填写的配置值不会上传。
- Web 控制台会显示你分享过的插件及其审核状态。

发布者签名证明插件由谁发布、文件发布后没有被改动，但并不代表代码已被认定为安全。

### Space 与插件

- 定义空间从设置移到了**扩展**页面，与插件放在一起。
- 分享或导出的 Space（`.zerospace`）包含该 Space 中编写的 definitions——包括它自己的 Skill、脚本和 MCP server——以及对其 Agent 所用插件的引用，但从不包含插件本身。
- 导入 Space 时，The One 会根据这些引用推导出其 Agent 需要哪些插件，你可以单独安装其中支持当前设备的插件。
- 从本地导入 `.zerospace` 文件时，现在会和从分享平台导入一样，在写入任何内容之前先显示预览。
- 之后的一次 0.4.x 更新让复制 Space 时连同已安装的插件一起复制；在此之前，副本不会带上插件。

## 即将发布：移除三种登录方式

0.4.28 之后的下一个版本将移除三种接入模型供应商的方式：

- Claude Code 登录
- Gemini CLI Code Assist 登录
- Gemini Antigravity Code Assist 登录

Claude Code、Gemini CLI 与 Antigravity 的条款都不允许第三方应用使用它们的登录，因此 The One 将不再提供这三种方式。用它们建立的连接在更新后将无法使用，也不会被自动迁移。Anthropic 与 Gemini 仍可通过 API Key 接入，OpenAI Codex 仍可用 ChatGPT 账号登录。保留的接入方式见[模型与价格](../models-and-pricing)。

## 总结

0.3.0 让 Agent 开始自我维持。0.4.x 给它们所用的能力一个真正的归属：插件可以作为一个整体被制作、分享、安装和审核，而 Space 引用插件，而不是复制插件。
