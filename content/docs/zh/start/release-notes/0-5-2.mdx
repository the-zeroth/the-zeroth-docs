这份记录覆盖 The One 0.5.2（macOS 和 Windows）和同时发布的 [Linux 服务器版](../linux-server) 0.5.2。它在 0.5.1 之后发布，应用的结构没有变：每个空间一个主助手，事项由工作组去做。Windows 上一个版本是 0.4.28，这次直接更新到 0.5.2，[0.5.0](./0-5-0) 和 [0.5.1](./0-5-1) 的变化也一并带上。

## 模型

- **设置 › 模型**里是一个**主模型**和五个**能力槽**：规划、编码、视觉、写作、快速。官方空间里的角色按要用的能力绑定能力槽；主助手和没绑能力槽的角色用主模型。详见[模型](../../the-one-app/capabilities/models)。
- 能力槽默认跟随主模型，用同一个模型，思考深度各有出厂设置：规划高，编码最高，视觉和写作中，快速低。主模型的思考深度不影响能力槽。想让某个能力换一个模型（可以是别家的）或换深度，点它的**更改**。
- 第一次设置时，连好模型服务后，主模型一栏会直接填上这家的旗舰模型，思考深度为中；可以直接保存，也可以换一个。
- 以前按名字保存的预设照常能用，列在**其他保存的模型配置**里，可以删除；应用不再新建预设。
- gpt-6.2-sol 和 gpt-6.2-astra 有了标价，用它们的运行不再记成 $0。

## 软件团队

- 软件团队 7.0 是一个负责人：先弄清要什么，想好做法，像使用者那样检查做出来的东西，再交付。它自己动手做，只有你要求时才把活分给子 Agent。
- 分活用的是 GPT 模型熟悉的 Codex 协作方式。剧场里这些协作步骤用文字显示，子 Agent 的提问和回答写明是对它的上级说的。
- 主助手按一件事要怎么做来分派，而不是按它属于哪个领域：要在你的电脑、文件夹或系统上动手做、跑起来检验结果的工作（代码、脚本、服务、数据处理、分析、模型），都交给软件团队。

## 你的做事方式

- 你说过的做事方式（比如“交付前先跑一遍测试”）会存成这个空间的长期规则，之后每个任务里的每个 Agent 都会看到并照做。
- 你纠正过的地方也会记下来；纠正的事已经有规则管着，就改写那条规则。
- 复制空间时，规则跟着复制；删除空间时，规则一起删掉。见[主助手](../../the-one-app/main-assistant)。

## 等你的事和周报

- 去掉了**需要你**和**晨报**两页：等你的东西只在对话上方那一条里处理，侧栏在**对话**旁边显示数量；每天的新消息由主助手在对话里问候时告诉你。
- 侧栏新增**周报**，回看最近七天：夜间回顾改了什么、每个事项、交付了什么和哪些失败了、无法撤回的动作、触发器，以及花费。
- Agent 真的对外做了无法撤回的事（付款、部署或发布网站、发邮件、推送代码），当场就用系统通知告诉你，不再等到下一次问候。
- **自动做事**放在侧栏底部，打开定时和触发的设置。

## 界面

- 整个界面大一号：最小的字从 12px 变成 13px，对话正文 16px，窗口宽过 1640px 时 17px。
- 事项页的主栏显示正在为这件事干活的工作组和 Agent，画法和全景一样；原来的工作组页并入全景。
- 一个没有活在做的空间，会显示做出来的东西、谁在待命、怎么开始，不再在每块面板里写“无”。
- 随应用发布的只读空间统一显示为**官方空间**。
- 上手的第一页只列一遍步骤；设置模型这一步只问一个问题。
- 英文界面里的单复数、逗号和冒号按英文写；编辑器的标签、技能栏和全景的流动不再换行、截断或重叠。

## Linux 服务器版

- `the-one-server run --assistant` 把任务交给空间的主助手，由它决定交给谁做，和在应用里跟主助手说一样。
- 服务器和桌面用同一套主模型和五个能力槽：`the-one-server model` 查看，`the-one-server model set` 修改主模型（`main`）或某个能力槽；`run --effort` 同时设定主模型和没有单独写深度的能力槽。
- `run` 打印交付时，恰好在空格处被截断的交付也会完整打印。

## 其他

- Agent 运行的命令不再带上应用给自己的服务设的 Python 环境变量。以前在打包的 macOS 应用里，Agent 的 python3 因此读不到装在你用户目录里的包，刚用 pip 装好的也一样。
