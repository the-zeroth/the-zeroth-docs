**工作组模板**写的是一类活怎么分工：哪些角色参与、谁可以把活交给谁、结果怎么验收。主助手把一个事项的活派出去时，会新开一次某个模板的运行，这次运行就是一个[工作组](../working-groups)。

模板就是 Graph：编辑页、它的标签（**Graph**）以及所有运行里的运行，都还这么叫。在**团队与工具**上，工作组卡片的**看看它会什么**会在这个编辑页里打开它的模板；编辑页左边的列表（**Graphs**）里列着空间的模板，其他编辑页列表上方的 **Graph** 标签也能打开它。

## 模板怎么变成工作组

- 主助手看得到空间里的每个模板，以及它描述的前 800 个字符，按描述为每件活挑一个。项目里的软件活交给 `polished_software_dev`，工作室对口的活交给对应的工作室，普通的多步工作交给 `chat`。
- 每派一次活，就新开一次这个模板的运行，在这件活所属的文件夹里干。你的要求按你的原话交给模板的入口节点（见下文）；从那以后，事项看板上的一张**工作组**卡片跟着这个组。
- 一个模板可以同时有几个工作组在干活，各自为不同的事项。团队与工具上它的卡片写着这些事项，比如**在为 2 件事干活：**，后面是事项的标题。
- 派活时可以只为这一次运行选模型，模板和角色都不用改，比如你要求某件活用更强的模型时。见[模型](./models)。
- 保存模板之后，新开的工作组用新版本；已经在干活的组还按原来的连线协作。
- [全景](../panorama)把每个工作组照它的模板画出来：谁能把活交给谁，活从哪个节点进来。

主助手是按描述挑模板的，所以描述要写给它看：这个模板适合什么活，不适合什么活。

## 搭一个模板

官方空间是只读的，模板要在你能改的空间里改。在官方空间里，上方有一条提示说明这一点，旁边的**复制一份以编辑**会复制整个空间并切换过去，在副本里下面这些都能做。复制之前，**新建 Graph** 和**保存**是灰的，改名的铅笔和删除用的 ✕ 也不出现；模板照样能看、能校验、能导出、能用**开始任务**跑，画布上也能试着改，只是存不下来。

画布上方的工具栏里依次是：模板的默认模型、**+**（**新增节点**）、⚡（**校验 Graph**）和**保存**；选中节点或连线时，还多出一个垃圾桶。**+**、⚡ 和垃圾桶只有图标，鼠标停在上面会显示名字。

1. 在列表（**Graphs**）上方点**新建 Graph**，填上**蓝图 ID**（主助手和模板文件用的名字）和**描述**。
2. 点 **+** 添加节点。每个节点都是一个活的 Agent，必须绑定一个[角色](./roles)：选中节点，在**节点检查器**里选它的 **Agent 预设**。新节点叫 `agent_1`、`agent_2`……，可以在**节点 ID** 里改成好认的名字，连着它的连线会跟着改。节点 ID 是这个 Agent 在运行里的名字，移交和选模型时都认它。
3. 同一个检查器里，**自定义系统提示词**（追加）只为这个节点在角色自己的提示词后面再加一段，所以同一个角色可以在不同模板里担任不同的分工。**节点插件**只给这个节点添加整个插件；节点已经从角色或整个模板拿到的插件，会标着它们来自哪里。
4. 从一个节点的输出口拖到另一个节点的输入口，把它们连起来；再选中这条连线，写它的移交说明（见下文）。
5. 在检查器里点**应用修改**，再点**保存**（Cmd/Ctrl+S）。检查器里的改动要先应用，保存时才会带上。

工具栏里的下拉菜单是模板的默认模型：一个模型预设，给角色没有单独指定模型的每个节点用。选**跟随默认模型**，这些节点就用全局默认模型。它和角色、运行各自的模型谁优先，见[模型](./models#模型的优先顺序)。

要删掉节点或连线，选中它，点工具栏的垃圾桶，或者按 Delete 键；删掉节点会连同它的连线一起删掉，连线检查器里也有**删除连线**。要删掉整个模板，在列表里把鼠标移到它上面，点 ✕，确认后删除。

模板名字旁边的铅笔用来改它的 ID 和描述。**开始任务**在任何事项之外把模板跑一次，和所有运行里的**新建 Graph** 一样，适合试一试模板；开出来的运行在[所有运行](../settings/all-runs)里打开。

## 入口和校验

**入口**是先接活的那个节点：派给这个模板的活，第一个交到它手里。画布上，入口节点的上沿挂着一个**入口**标签。模板记着入口是哪个节点；用编辑器保存时，还没记入口的模板会把画布上的第一个节点记成入口，一般就是你最先加的那个。

想让别的节点先接活，就选中它，在**节点检查器**的**入口节点**下点**设为入口节点**，再保存。改入口节点的**节点 ID**，它仍然是入口。删掉入口节点时，入口会移到另一个节点上，并提示移到了哪个：**入口已移到「…」**。如果模板文件里记的入口节点不在图里，工具栏会写着**入口「…」不在图中**，哪个节点都不挂入口标签；把其中一个节点设为入口再保存就好。

**校验 Graph**（⚡）检查的是已经保存的版本，所以先保存再校验。它显示**校验通过**，或者一共几个错误、几个提醒，比如 **2 个错误 · 1 个提醒**，这时工具栏下方会展开**校验结果**；点这个结果可以收起或再展开。每一条写明哪里不对、指向哪里（整个 Graph、某个节点或某条连线）；点一条指向节点或连线的，画布上就选中它。

- 标着**错误**的是这几种：一个节点都没有；入口节点不在图里，或者模板没记入口、又找不出唯一一个没有连线指向的节点；连线连到了不在的节点；Agent 节点既没选 **Agent 预设**，也没有自己的模型。
- 标着**提醒**的是：节点选的角色不在当前空间里，比如后来被删掉了。只有提醒时，校验照样通过（比如**校验通过 · 1 个提醒**），这个节点的检查器里也写着预设不可用；但在你给它换一个角色之前，派给这个模板的活开不起来。

校验本身没能进行时，比如后台没有响应，会弹出提示说明原因，不会把它算成模板的错误。

## 连线是什么意思

连线不是固定的流水线。从 A 到 B 的一条连线是一种许可：A 可以把活交给 B。A 一交出去就进入休眠，B 醒来，收到的正好是 A 这次移交写的内容和文件，A 上下文里别的东西它都看不到。要不要交、什么时候交，由 Agent 在运行中自己判断，或者听你的。

- 连线是单向的。要让 B 把结果交回来，再加一条从 B 到 A 的连线。
- 没有连线，A 就不能把活交给 B。不过，持有 graph 工具的负责人仍然可以启动任何节点，和自己并行干活；用 TaskBoard 的负责人，会把任务派给完全没有连线的工人节点，`polished_software_dev` 里的 `developer` 就是这样的工人。Agent 在运行中也可以自己加连线。
- 负责移交的那个 Agent，会在自己的指令里看到它能交给哪些节点，以及每个节点角色的描述和那条连线上的文字。

正因为这样，连线上的文字很要紧。**连线检查器**里的**转移说明（handoff 指令）**，就是交出去的那个 Agent 在移交那一刻读到的指令，所以要写完整：什么时候交、把什么交过去、希望对方产出什么。比如：“评审通过后，把完整的方案、API 契约和数据模型交给开发节点，请它据此写出能跑的代码，并附上测试。”写得越具体，协作越准确。

## 导入和导出

列表上方**新建 Graph** 旁边的**导入**按钮（鼠标停上去写着**导入 Graph**，窗口窄时只剩图标），把为别的工具写的团队变成这个空间里的模板。它能读 Oracle 的 **Agent Spec**、**Dify DSL** 文件和 **Microsoft Declarative Workflow**：选一个 .yaml、.yml 或 .json 文件，或者把内容粘贴进来，最多 500 万个字符。格式按内容自动判断，也可以在**格式**里自己选。**Graph ID**（可选）留空，就用文件里的名字。文件里的每个 agent 变成一个角色，它们怎么协作变成连线。

- **预览**在写入之前列出模板、它的 agent 和连线，以及**转换报告**；**导入**才真正写进空间。勾选**覆盖已有**会替换同名的模板或角色。
- 不会悄悄丢东西。转换报告列出每个**没带过来**和**换了样子**带过来的字段，并写明它在文件里的位置。
- 有些东西从来不转过来。导入的角色用你的默认模型，报告里写着文件原本要的是哪个模型。The One 里没有对应的工具，会连同用它的 agent 一起列在报告里。密钥不会进模板，报告里只写它们的名字。
- The One 没有跑固定步骤的引擎，所以一串固定步骤（Agent Spec 的 Flow、Dify 的工作流、带分支的 Declarative Workflow）会变成一个领头的 Agent，它的提示词按顺序写出每一步；这些步骤里调用的 agent 变成团队成员，由领头的把那一步交给它们。

![导入 Dify DSL 文件和它的转换报告](/docs-assets/images/0.5/zh/working-group-templates-import.png)

**导出**把最近一次保存的版本写成 Agent Spec 26.1.2（YAML 或 JSON）、Dify DSL 文件，或者微软的 Python 包 `agent-framework-declarative` 能直接运行的 Declarative Workflow。技能、插件、模型设置和默认模型预设不会带出去，转换报告里会写明。文件的元数据里存着 The One 自己的连线，所以原样导入回来，还是同一个模板。

官方空间里的模板能导出，但不能导入或预览，见[在官方空间里能改什么](../capabilities#在官方空间里能改什么)。

## 怎么设计一个模板

出厂的团队是按几条原则搭的，自己设计时也值得照着做：

- 先有一个工具齐全、对结果负责的负责人。只为别人看不到、做不到的事加节点：不同的输入、更窄的上下文、不同的模型，或者有用的并行。同一个角色拿着同样的输入多开几份，只会在同一处出错。
- 检查员在开工时就启动，和动手的人并行，让它们的发现在该做决定之前就到。
- 给检查员的是需求、数据和接口，不是它要检查的成果：读了实现的检查员会继承实现的错。
- 规则放在用到它的地方：放进它管的那次移交里，或者放进一个技能里（见[技能与提示词](./skills-and-prompts)）；不要放进角色常驻的提示词，那里的规则在用不上的时候也在起作用。
- 负责人的路径就是成本：路径上每多一跳都要多几轮。节点数是结果，不是目标。

模板不一定要你亲手搭，主助手和总图的 The Director 指令栏都能写，见[谁能修改](../capabilities#谁能修改)。在 [A-Genetic Engineering（Agent 基因工程）](../../multi-agent-architecture/a-genetic-engineering)里，模板连同它的角色就是一个工作组的基因；Agent 在运行中继续把工作组长大（克隆 Agent、开子图），就是 [Prolifera Engineering（增殖式工程）](../../multi-agent-architecture/prolifera-engineering)。
