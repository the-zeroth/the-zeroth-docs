**角色**是把工作组里的一个 Agent 写下来：它做什么、用哪个模型思考、能用哪些提示词、技能、工具和插件。[工作组模板](./working-group-templates)里的每个节点都绑着一个角色，所以一个角色可以在好几个模板里出场，扮演它的每个 Agent 都从同一份定义出发。

能力页面叫它们**角色**；编辑页（标签是 **Agent**）把每个角色叫作 Agent 预设。从**能力 › 角色**打开一个，或者在列表上方选**新建 Agent**。

编辑页有三个标签：**基础配置**、**提示词**和**能力**。改动在保存时生效：之后组建的工作组直接用上；已经在干活的 Agent 从下一轮起用上，正在生成的那条回复照原样写完。

## 基础配置

### 名称和描述

**名称**就是角色的 ID。之后改名，继承它的角色和用到它的模板会一起跟着改。

**描述**写这个角色擅长什么。Agent 也会读它：能把活交给这个角色的 Agent，会在自己的可移交对象列表里看到这段描述，所以要写给它们看。

### 继承

在**继承**里选另一个角色，这个角色就以它为底。之后每一项都标着**继承中**或**覆盖**：把某一项切到“覆盖”，就在这里单独设置。一族相近的角色可以共用一个底座，只维护各自的差别。

### 模型

在**模型与参数**里，角色有三种方式拿到模型：

- **用模型预设**：在**模型预设**里选一套已保存的预设，模型、连接、思考强度和服务等级一起定。预设改了，角色从下一轮起跟着变。
- **使用默认模型**：角色跟随全局默认模型，在**设置 › 默认模型**或标题栏的模型菜单里设置。编辑页会显示**当前默认**是哪个。
- **单独配置**：两样都不选，在这里设置 **API 配置**（连接）、**速度 / 服务等级**、**模型**和**思考 (Reasoning)**。

这里没有 temperature 一项：由模型服务商用它自己的默认值。

Agent 每一轮开始时，按下面的顺序取第一个适用的模型：主助手只为这次运行选的模型，然后是角色自己的，然后是在**设置 › 所有运行**里给这次运行设的默认模型，然后是模板的默认预设，最后是全局默认。所以没指定模型的角色，用模板或全局默认的那一个；主助手要给某个工作组换更强的模型，也不用动角色。见[模型](./models)。

**组成与来源**汇总了这个角色由哪些部分组成，以及每一部分来自哪里：自己的设置，还是继承来的。点其中一行，就跳到那一部分。

## 提示词

- **结构化 Prompt** 挂载**能力 › 提示词**里的提示词。选中一条可以预览，**编辑**会在提示词编辑页里打开它。几段小提示词组合起来，比一段大提示词好用；许多角色都挂着的一段提示词，改一处就够了。比如官方空间里的每个角色都挂着共用的 `Agents' cognition`。
- **附加 Prompt** 是只属于这个角色的一小段提示词。

Agent 读到的顺序是：先是角色自己的提示词（附加 Prompt），再是它挂载的提示词，最后是模板为这个节点追加的文字。见[技能与提示词](./skills-and-prompts)。

## 能力

角色能做什么，就看你在这里给了它什么。它用自己手里的东西时，不会停下来等谁批准：每一次调用都记在**设置 › 行动记录**里，对文件的改动可以在那里撤回。见[行动记录、撤回和急停](../action-log)。

### 插件

选这个角色能用的插件。插件是整个加进来的，连同它的技能、脚本、外部工具、应用和连接：**添加整个插件**加进来；确实需要时，**高级组件设置**可以只挑其中几个组件。标着**必需**的插件，装好了这个角色才能运行。**打开插件中心**可以安装插件、管理它们的连接。

也可以反过来：在插件库里点**添加给 Agent**，把插件加给你选的角色。见[插件与应用](./plugins)。

### 工具

**工具**是内置的工具集：读写文件、运行命令、上网、和你对话、用 TaskBoard 派任务、开子图、记忆，等等。展开一个可以看到它的**暴露函数**并关掉其中某几个，填写它的**实例配置**，或者在工具描述后面追加使用约束。

标着**完全本地访问**的工具，以你这个系统用户的权限访问文件、网络和进程。这个标记是在说明它能做什么，并不限制它。

### Skills

选**全部**，这个角色就拿到空间里的每个技能，包括以后新加的；选**自选**就逐个挑。技能在 Agent 的上下文里只是一张简短的卡片，活儿用得上时才打开，所以列表长一些也不费什么。

### MCP 服务器

选**全部**，空间里的每个外部工具服务器都给这个角色用，包括以后新加的，新加的从 Agent 的下一轮起就能用；选**自选**就逐个挑。[外部工具（MCP）](./mcp)页面只负责定义连接，角色在这里拿到它们。

在官方空间里，主助手和 `chat` 工作组的助手拿到全部内置工具、技能和服务器；团队里的角色只拿各自活儿需要的。比如软件团队的方案负责人，有文件、命令、上网、TaskBoard、graph 工具和 Chrome DevTools 服务器。

## 原文、内置角色和官方空间

- **原文**只读地显示这个角色保存在磁盘上的文件，以及它在空间里的路径。
- 内置角色（`main-assistant`、`chat-assistant`、`atlas-director`、`nightly-reviewer` 和进化实验室的三个角色）和别的角色一样列在这里，在你自己的空间里也能改。主助手是你所有事情都会经过的那个对话，改它要小心。
- 在官方空间里，编辑页是只读的。**复制一份以编辑**会复制这个空间，并切换到副本。见[定义空间](./definition-spaces)。

## 还有谁会改角色

角色不一定要你亲手改。你开口，主助手就能写新角色或改现有的；[总图](./atlas)画布底部的 **The Director** 指令栏会当着你的面改。证据表明某个角色该改时，进化实验室也会改它。见[进化：实验室和夜间复盘](../evolution)。

一个角色，连同它所在的模板和其他成员，构成一个可复用工作组的基因：见 [A-Genetic Engineering（Agent 基因工程）](../../multi-agent-architecture/a-genetic-engineering)。
