事项是你关心的一件事，比如一个功能、一家网店或一次旅行，形式是一块由卡片组成的看板。你、主助手和工作组读写的都是同一块看板，所以在这里总能看到什么在等你、发生了什么、工作到了哪一步。

## 事项从哪里来

- 大多数事项由主助手开：你要的事比一句回答大，它就开一个事项，并在同一步把活交给一个工作组。见[主助手](./main-assistant)。
- 你也可以在事项总览里按**自己开一个**，先记下笔记，再把事交出去。
- 工作组可以为自己的一部分活开一个子事项（见下面）。
- 用你的团队干活的外部程序，每交来一个任务都放在一个事项上：它指定的那个，或者新开一个。见[随身通道和对外调用](./remote)。

事项不等于一次运行。几个工作组可以同时做一个事项，也可以一个接一个地做，有一段时间也可能谁都不在做。事项属于你当前所在的空间。

## 侧边栏里的事项

开着的事项列在侧边栏的**事项**下面，每个前面一个色点。等你的排在最前，然后是出了问题的、正在做的，最后是已交付的和没动静的；同一类里最近改过的在前。在等你或出了问题的事项，标题下面多一行写着怎么了；其余的只占一行，鼠标停上去能看到它那一行。**事项**这个标题写着开着的有几个，比如**全部 4**，点它打开事项总览（见下面）。

那一行写的是下面这些，事项总览和[全景](./panorama)上也是同样的说法：

| 那一行写着 | 意思 |
| --- | --- |
| **到了用量上限，等你继续** | 它的活停在了你设的边界上。到事项页恢复它。 |
| **模型连接要你处理** | 有模型连接拒绝了它工作组的活（密钥、权限或套餐），只有你能修好。 |
| **1 个问题等你回答**、**2 份交付等你验收**，或者 **1 个问题、2 份交付等你** | 有问题和交付在等你，子事项的也算在内。 |
| **有工作组没做成** | 有工作组的运行失败了。 |
| **出错了，正在自动重试**，或者 **2 个成员出错，正在自动重试** | 有 Agent 一直出错，正在自己重试。 |
| **工作组在做**，或者 **2 个工作组在做** | 工作在进行。 |
| **排队中** | 它的工作组要先做完别的事项的活。 |
| 一句自己的话 | 上面几种都不是，显示的就是主助手维护的一句话现状。 |
| **已交付** | 工作组交付了，没有等你的事。 |
| **常驻 · 等下次触发** | 现在没在做什么，下一份活由它的触发器带来。 |
| **还没开工** | 还没有工作组开工。 |

鼠标移到一个事项上（或用键盘走到它），右边会露出结束按钮，见下面的[结束和重新打开](#结束和重新打开)。列表下面的**新事项：对主助手说**带你到主助手的输入框。已结束的事项会离开这个列表，在事项总览的**结束了**里能看到。事项上面的**全景**把所有开着的事项和它们的工作组画在一页上，见[全景](./panorama)。

## 事项总览

事项总览的标题是**事项**，每个开着的事项一行：色点和一行现状、在为它干活的工作组（用中文名，比如**软件团队**），以及最后改动的时间。这些行分四段：**等你**、**在做**（有工作组没做成或一直出错的也在这里）、**定时**（活由触发器带来的事项）和**其余**。上面的筛选（**全部**、**等你**、**在做**、**定时**和**结束了**）可以只看其中一段，或者只看你结束的事项；**搜索事项**按标题或一句话现状找事项。

右上角的**新事项：对主助手说**带你到主助手的输入框；**自己开一个**手动开一个事项，适合先记下笔记、再把事交出去的时候。填好**标题**和**这是什么事，要做到什么程度**，按**开事项**，就会进到它的看板。主助手会在它的事项列表里看到它，你再告诉它要怎么做。

## 页头

打开一个事项，最上面是它的标题、一句话现状（还没有时写**还没有一句话现状**）、**已结束**和**常驻**这样的标记，以及它的**花费**（见下面的[花费和边界](#花费和边界)）。子事项的标题上面写着**子事项**，还有一个**回到「…」**，点它就回到所在的事项。

事项的按钮在窗口右上角：

- **审阅**（有工作组运行以后才有）：看每个工作组改了什么、做出了什么。见[工作组](./working-groups#审阅)。
- **提成顶层事项**（子事项上才有）。
- **改标题和现状**。
- **结束事项**；已结束的事项上是**重新打开事项**。见下面的[结束和重新打开](#结束和重新打开)。

有工作组在做这件事以后，看板上方最左边有一个开关，在**看板**和**剧场**之间切换。剧场在一屏里显示所有工作组的 Agent 正在做什么，见[剧场](./working-groups#剧场)。在[全景](./panorama)上点一个工作组的名字，打开的也是这里的剧场。

## 看板

页头下面是事项的看板，分左右两栏。

左边一列从上到下：

- **等你**：这个事项或它的子事项上等你处理的事，比如工作组问你的问题、等你评判的交付，每件写着来自哪个工作组。它们和主助手对话里、对话上方那一条和全景上的是同一张卡，直接在卡上回答、验收或恢复（见[等你和交付](./needs-you)）。同一份活只有最新那次交付在这里等你，之前的算历史。一个提问或交付处理过以后，看板自己的那张**提问**或**交付**卡在“进展”里。
- **工作组**：在做这件事的每个工作组一张卡，标题旁写着有几个 Agent 在干活。卡上画着这个组现在的 Agent，和[全景](./panorama)上画的一样：每个 Agent 一行，写着它此刻在想、在调工具、在等谁，还是出错了。旁边是交给它的活、它的文件夹和卡上的按钮（见下面的[卡片](#卡片)）。点一个 Agent，看板旁边打开全景上的那个面板，写着它在做什么、刚做了什么，可以**打开对话**或**看剧场**；按 Esc 关上。这个事项下面开着的子事项，它们的工作组也画在这里，各自连到自己的子事项。
- **数据和面板**：数据卡和面板卡，它们需要宽一点的地方。
- **进展**：其余的卡片，新的在上面，按天分开，每条写着最后改动的时刻。长的内容先折起来。

没有事在等你、也没有工作组在干活时，左边一列换成另一种开头：先是**最近交付**，最近那份交付的整张卡，带着你的结论和证据包；然后是**这件事做出来的文件**，点一个打开它；再往下是数据和面板、工作组和进展。还没交给过工作组的事项写着**还没有人在做这件事**，旁边是**去跟主助手说**。

右边是**这件事本身**：

- **目标**：概述卡，写这件事是什么、要做到哪一步。
- **节奏**：事项有触发器时的节奏卡。
- **清单、链接和文件**。
- **子事项**（有的话）。
- 自己加笔记、清单、链接或文件卡片的按钮。

每张卡片头上写着它是哪种卡、是谁放的：**你**、**主助手**、某个工作组的中文名（比如**软件团队**），或者应用自己写的卡写 **The One**。提问卡和交付卡写的是它们来自哪个工作组；工作组卡（标题是这个组的名字）和节奏卡不写是谁放的。开发者视图里还会显示事项、模板和运行的 ID（见[设置](./settings)）。

![事项的看板：等你的事和在做它的工作组，右边是这件事本身：目标、节奏和清单](/docs-assets/images/0.5/zh/matters-board.png)

## 卡片

大家写的是同样的几种卡片，只有四种由 The One 照它自己的记录维护，别人不能写也不能删。这是为了让它们一直和记录对得上，不是权限上的限制。

| 卡片 | 谁写 | 内容 | 你能做什么 |
| --- | --- | --- | --- |
| **概述** | 谁都可以 | 这件事是什么、要做到哪一步。主助手拿交付对照它。 | 编辑或移除。 |
| **笔记** | 谁都可以 | 一段 Markdown 文字：一个决定、一个偏好、一个事实。 | 添加、编辑、移除。 |
| **清单** | 谁都可以 | 要勾的条目，最多 200 条。 | 直接在卡片上勾；添加、编辑、移除。 |
| **链接** | 谁都可以 | 一个地址，可以带说明；The One 可以替你查网址还能不能打开。 | 添加、编辑、移除；**现在查**、**固定**。 |
| **文件** | 谁都可以 | 文件路径，一行一个。 | 打开文件；添加、编辑、移除。 |
| **数据** | 主助手或工作组 | 一个来源现在怎么说：插件工具、文件或文件夹、网页或命令，显示成一个数、一张表、一条折线或一段文字。 | **现在读**、**固定**、改标题、移除。 |
| **面板** | 主助手或工作组 | 一个插件工具的面板，钉在看板上给你用。 | 用面板、**重新载入**、改标题、移除。 |
| **工作组** | The One | 一个在做这件事的工作组：状态、**交给它的活**、**文件夹**，以及最后是谁跟它说话。 | **和这个组说话**、**暂停**或**继续**、**先做这个**、**现在重试**。见[工作组](./working-groups)。 |
| **提问** | The One | 工作组提的问题和选项，以及是谁答的。 | **去回答**打开提问的那个 Agent 的对话。 |
| **交付** | The One | 工作组交回的工作、这份活现在怎样，以及它的**证据包**。 | **接受**、**返工**、**放弃**；**打开对话**。 |
| **节奏** | The One | 事项的触发器：每个在等什么、活交给谁，下次和上次什么时候触发。 | **现在触发**、**暂停**或**恢复**。见[触发器和后台常驻](./triggers)。 |

### 数据卡

数据卡显示一个来源现在怎么说：插件工具的回答、一个文件或文件夹、一个网页，或者一条命令的输出。数据卡由 Agent 来写，想要一张就跟主助手说，比如“把这周的订单做成一张表放到看板上”。The One 自己去读这个来源，读法和写卡的 Agent 自己去读一样，读到的东西都画成纯文字和数字。

- 卡片在屏幕上、又到了该再读的时候，它就读一次。卡上写着什么时候读的、每隔多久可以再读。
- “现在读”会马上读一次。固定以后，只要事项还开着、又在当前空间里，The One 运行时就按间隔一直读它，没人看也读；**取消固定**就停下。
- 没读到时，卡上照样显示上次读到的内容，并写明最近一次为什么没读到。

数据卡上的内容来自外面。Agent 读看板时，这些内容被标成外部数据：是要核对的事实，不是要照做的指令。

### 链接检查

在链接卡上勾选**时不时打开看看还能不能打开（网址才行）**，卡片在屏幕上时，The One 最多每五分钟打开一次这个地址；固定以后，只要事项还开着、又在当前空间里，没人看也按时查。卡上写着能不能打开（带 HTTP 状态和花了多久）、打开时回答了错误，还是打不开；地址跳转时，写着跳到了哪里。“现在查”会马上查一次。没勾选的链接，The One 从来不会去打开。

### 面板卡

面板卡把一个插件工具的面板放到看板上，比如一家店的订单列表。它占看板一整行，第一次进到屏幕里时才载入。面板由 The One 替你运行，而不是钉它的那个 Agent，所以那个 Agent 做完了，面板照样能用。工具只读时，面板一打开就显示它现在怎么说；会改东西的工具，不会只为显示面板去运行。按“重新载入”会再载入一次。

你经面板做的事算你自己的：这些调用在行动记录里记成你经看板上的面板做的，算进这个事项的改动，也能撤回。面板只在桌面应用里显示。

### 版本和编辑

卡片每保存一次都留一个版本，移除的卡片也留着历史。你打开一张卡编辑以后，如果别人又改过它，你的保存会被拒绝，看板换成新的版本，在新版本上再改就好。一张卡最多 64 KB，更长的内容放进文件，卡片上写路径。

## 花费和边界

页头的**花费**平时只写一个数：花了多少钱（算不出价钱时写 token 数）。点它展开一行：花了多少钱、多少 token、其中**无人值守**的有多少，以及边界（**没设边界**，或者**边界**后面跟着上限），旁边是**设边界**或**改边界**。鼠标停在这些数上，能看到模型调用次数、命中缓存的量，以及有几次调用没有价格。

它统计的是这个事项的工作组为它干活时得到的每一次模型回应，子事项也算在内。无人值守是你最近一次介入以后花的：你对它某个工作组发的消息、回答、改了重发或重试，或者由主助手转达的你的话。

**设边界**限制无人值守最多能花多少，单位是百万 token（最少 0.01，也就是 1 万 token）。工作组花到这么多，活就停在下一个检查点（正在做的那一步先做完），页头下面出现一条横幅写明花了多少，你也会收到提示。横幅上的**恢复**让活接着做，并从零重新算起。**改边界**可以改上限，也可以**去掉边界**。

- 边界也管着这个事项的子事项。
- 快到边界时（用到 80%），正在干活的 Agent 会被告知这个事项的活会停在那里。
- 同时替别的事项干活的工作组，在这个事项的活停着时，照样做别的事项的活。
- 主助手只照你的话设边界，或者恢复停下的活。

## 改动和撤回

看板下面的**改动**写着这个事项的工作组改过几个文件、其中能放回几个，展开能看到是哪些。**撤回这些改动**先给你预览，确认后把每个文件放回这个事项的活第一次改它之前的样子，子事项的活也算在内。之后又被改过的文件不动，除非你确认覆盖。撤回本身也记下来，所以还能再撤回。详见[行动记录、撤回和急停](./action-log)。

## 结束和重新打开

不再管一件事时，就结束它。有两种结束法：

- 在事项页右上角按**结束事项**，一下就结束；鼠标停在按钮上，会写着结束意味着什么。
- 在侧边栏或[全景](./panorama)上，鼠标移到一个事项上（或用键盘走到它），右边会露出结束按钮。按下去 The One 会再问一次（**结束「…」？**），免得一下按错停了工作组的活。这个事项和它的子事项还有事在等你时，对话框先说有几件，列出前三件：**先去处理**不结束，带你去事项页处理它们；**结束事项**才结束；**取消**什么都不做。

结束以后：

- 为它干的活停在手上那一步，它的触发器也停下。当时还在干活的工作组做完这一步就停，组卡上写着**事项结束时它停下了，重新打开事项就接着做。**；节奏卡上写着**随事项暂停**。同时替别的事项干活的工作组，接着做别的事项的活。
- 它离开侧边栏和全景，在事项总览的**结束了**里能找到。
- 它和它子事项上的提问、交付和失败不再等你：从对话上方的**等你**、看板的**等你**和各处等你的数里收起来。周报里也不再等你：这 7 天交来的交付照样算进交付了几件，但写着**事项已结束，重新打开后再验收**，不带验收按钮。

结束不是评判：交付还在那里等你的结论，重新打开事项，它们就回到等你里。重新打开也让活从停下的地方接着做：停下的工作组继续，触发器也重新打开，从现在算起（结束期间错过的不补）。

你也可以让主助手替你结束或重新打开一个事项。

## 子事项

工作组可以把自己的一部分活开成一个子事项：这部分有自己的目标和交付，或者你可能想单独跟进它，比如一家店的 Logo。子事项列在它所在事项看板上的同名一栏里，不在侧边栏里；子事项页可以回到它所在的事项。在全景上，子事项不单独占一栏：它的工作组画在它所在事项那一栏里，写着**子事项「…」**。

- 子事项的提问先问开它的工作组。提问卡上写明了这一点；你直接对提问的 Agent 说，也算回答。
- 它的交付交给开它的工作组去用（**交给了开它的工作组**），不等你验收。
- 它的花费算进上面每一层事项，上面事项的边界也管着它。
- 结束子事项只停它自己的活；结束上面的事项，它也会一起停下，它上面等你的事也一起收起。

**提成顶层事项**会把子事项提到顶层：它会出现在侧边栏、全景和主助手的事项列表里，以后的花费只算它自己的，之前已经花的照旧算在原来的地方。它的提问还是先问开它的工作组。

## 常驻，以及进化事项

触发器开着的事项是常驻的：它的活会按时，或者在有新东西时，自己来。它的节奏卡列出每个触发器，以及下次和上次什么时候触发；事项总览的**定时**把这样的事项列在一起。主助手会为反复要做的事设好这些，比如每张新订单、新邮件或者每周的报告。详见[触发器和后台常驻](./triggers)。

你让主助手改进空间时，它为此开的事项会在看板上方显示实验室的读数和规矩。详见[进化：实验室和夜间复盘](./evolution)。
