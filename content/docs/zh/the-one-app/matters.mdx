事项是你关心的一件事，比如一个功能、一家网店或一次旅行，形式是一块由卡片组成的看板。你、主助手和工作组读写的都是同一块看板，所以在这里总能看到什么在等你、发生了什么、工作到了哪一步。

## 事项从哪里来

- 大多数事项由主助手开：你要的事比一句回答大，它就开一个事项，并在同一步把活交给一个工作组。见[主助手](./main-assistant)。
- 你也可以在首页按**自己开一个事项**，先记下笔记，再把事交出去。
- 工作组可以为自己的一部分活开一个子事项（见下面）。
- 用你的团队干活的外部程序，每交来一个任务都放在一个事项上：它指定的那个，或者新开一个。见[随身通道和对外调用](./remote)。

事项不等于一次运行。几个工作组可以同时做一个事项，也可以一个接一个地做，有一段时间也可能谁都不在做。事项属于你当前所在的空间。

## 侧边栏里的事项

进行中的事项列在侧边栏的**事项**下面，每个带一个色点和一行现状。等你的排在最前，然后是出了问题的、正在做的，最后是已交付的和没动静的；同一类里最近改过的在前。

| 那一行写着 | 意思 |
| --- | --- |
| **到了用量上限，等你继续** | 它的活停在了你设的边界上。到事项页恢复它。 |
| **模型连接要你处理** | 有模型连接拒绝了它工作组的活（密钥、权限或套餐），只有你能修好。 |
| **1 个问题等你回答**、**2 份交付等你看**，或者 **1 个问题、2 份交付等你** | 有问题和交付在等你，子事项的也算在内。 |
| **有工作组没做成** | 有工作组的运行失败了。 |
| **出错了，正在自动重试** | 有 Agent 一直出错，正在自己重试。 |
| **工作组在做** | 工作在进行。 |
| **排队中** | 它的工作组要先做完别的事项的活。 |
| 一句自己的话 | 上面几种都不是，显示的就是主助手维护的一句话现状。 |
| **已交付** | 工作组交付了，没有等你的事。 |
| **常驻 · 等下次触发** | 现在没在做什么，下一份活由它的触发器带来。 |
| **还没开工** | 还没有工作组开工。 |

列表下面的**新事项：对主助手说**带你到主助手的输入框。已结束的事项会离开这个列表，在首页勾选**显示已结束**就能看到。

## 看板

打开一个事项，看到的是它的看板，分左右两栏。

左边：

- **等你**：这个事项或它的子事项上等你处理的事，比如工作组问你的问题、等你评判的交付，每件写着来自哪个工作组。它们和主助手对话上面、“需要你”里的是同一张卡，直接在卡上回答、验收或恢复（见[需要你、交付和晨报](./needs-you)）。同一份活只有最新那次交付在这里等你，之前的算历史。一个提问或交付处理过以后，看板自己的那张**提问**或**交付**卡在“进展”里。
- **数据和面板**：数据卡和面板卡，它们需要宽一点的地方。
- **进展**：其余的卡片，新的在上面，按天分开，每条写着最后改动的时刻。长的内容先折起来。

右边是**这件事本身**：

- **目标**：概述卡，写这件事是什么、要做到哪一步。
- **工作组**：事项上的每个工作组一张卡；事项有触发器时，还有节奏卡。
- **清单、链接和文件**。
- **子事项**（有的话）。
- 自己加笔记、清单、链接或文件卡片的按钮。

每张卡片头上写着它是哪种卡、是谁放的：**你**、**主助手**、某个工作组的名字，或者应用自己写的卡写 **The One**。提问卡和交付卡写的是它们来自哪个工作组；工作组卡和节奏卡不写是谁放的。

## 卡片

大家写的是同样的几种卡片，只有四种由 The One 照它自己的记录维护，别人不能写也不能删。这是为了让它们一直和记录对得上，不是权限上的限制。

| 卡片 | 谁写 | 内容 | 你能做什么 |
| --- | --- | --- | --- |
| **概述** | 谁都可以 | 这件事是什么、要做到哪一步。主助手拿交付对照它。 | 编辑或移除。 |
| **笔记** | 谁都可以 | 一段 Markdown 文字：一个决定、一个偏好、一个事实。 | 添加、编辑、移除。 |
| **清单** | 谁都可以 | 要勾的条目，最多 200 条。 | 直接在卡片上勾；添加、编辑、移除。 |
| **链接** | 谁都可以 | 一个地址，可以带说明；The One 可以替你查网址还能不能打开。 | 添加、编辑、移除；**现在查**、**固定**。 |
| **文件** | 谁都可以 | 文件路径，一行一个。 | 打开文件；添加、编辑、移除。 |
| **数据** | 主助手或工作组 | 一个来源现在怎么说：插件工具、文件或文件夹、网页或命令，显示成一个数、一张表、一条折线或一段文字。 | **现在读**、**固定**、改标题、移除。 |
| **面板** | 主助手或工作组 | 一个插件工具的面板，钉在看板上给你用。 | 用面板、**重新载入**、改标题、移除。 |
| **工作组** | The One | 一个在做这件事的工作组：状态、**交给它的活**、**文件夹**，以及最后是谁跟它说话。 | **和这个组说话**、**暂停**或**继续**、**先做这个**、**现在重试**。见[工作组](./working-groups)。 |
| **提问** | The One | 工作组提的问题和选项，以及是谁答的。 | **去回答**打开提问的那个 Agent 的对话。 |
| **交付** | The One | 工作组交回的工作、这份活现在怎样，以及它的**证据包**。 | **接受**、**返工**、**放弃**；**打开对话**。 |
| **节奏** | The One | 事项的触发器：每个在等什么、活交给谁，下次和上次什么时候触发。 | **现在触发**、**暂停**或**恢复**。见[触发器和后台常驻](./triggers)。 |

### 数据卡

数据卡显示一个来源现在怎么说：插件工具的回答、一个文件或文件夹、一个网页，或者一条命令的输出。数据卡由 Agent 来写，想要一张就跟主助手说，比如“把这周的订单做成一张表放到看板上”。The One 自己去读这个来源，读法和写卡的 Agent 自己去读一样，读到的东西都画成纯文字和数字。

- 卡片在屏幕上、又到了该再读的时候，它就读一次。卡上写着什么时候读的、每隔多久可以再读。
- “现在读”会马上读一次。固定以后，只要事项还开着、又在当前空间里，The One 运行时就按间隔一直读它，没人看也读；**取消固定**就停下。
- 没读到时，卡上照样显示上次读到的内容，并写明最近一次为什么没读到。

数据卡上的内容来自外面。Agent 读看板时，这些内容被标成外部数据：是要核对的事实，不是要照做的指令。

### 链接检查

在链接卡上勾选**时不时打开看看还能不能打开（网址才行）**，卡片在屏幕上时，The One 最多每五分钟打开一次这个地址；固定以后，只要事项还开着、又在当前空间里，没人看也按时查。卡上写着能不能打开（带 HTTP 状态和花了多久）、打开时回答了错误，还是打不开；地址跳转时，写着跳到了哪里。“现在查”会马上查一次。没勾选的链接，The One 从来不会去打开。

### 面板卡

面板卡把一个插件工具的面板放到看板上，比如一家店的订单列表。它占看板一整行，第一次进到屏幕里时才载入。面板由 The One 替你运行，而不是钉它的那个 Agent，所以那个 Agent 做完了，面板照样能用。工具只读时，面板一打开就显示它现在怎么说；会改东西的工具，不会只为显示面板去运行。按“重新载入”会再载入一次。

你经面板做的事算你自己的：这些调用在行动记录里记成你经看板上的面板做的，算进这个事项的改动，也能撤回。面板只在桌面应用里显示。

### 版本和编辑

卡片每保存一次都留一个版本，移除的卡片也留着历史。你打开一张卡编辑以后，如果别人又改过它，你的保存会被拒绝，看板换成新的版本，在新版本上再改就好。一张卡最多 64 KB，更长的内容放进文件，卡片上写路径。

## 页头

页面最上面是事项的标题、一句话现状、**已结束**和**常驻**这样的标记，以及它的花费。按钮有：

- **审阅**（有工作组运行以后才有）：看每个工作组改了什么、做出了什么。见[工作组](./working-groups)。
- **提成顶层事项**（子事项上才有）。
- **改标题和现状**。
- **结束**；已结束的事项上是**重新打开**。

有工作组在做这件事以后，看板上方有一个开关，在**看板**和**剧场**之间切换。剧场在一屏里显示所有工作组的 Agent 正在做什么。

## 花费和边界

**花费**这一行统计这个事项的工作组为它干活时得到的每一次模型回应，子事项也算在内：花了多少钱、多少 token、其中**无人值守**的有多少，以及边界。鼠标停上去能看到模型调用次数和命中缓存的量。无人值守是你最近一次介入以后花的：你对它某个工作组发的消息、回答、改了重发或重试，或者由主助手转达的你的话。

**设边界**限制无人值守最多能花多少，单位是百万 token（最少 0.01，也就是 1 万 token）。工作组花到这么多，活就停在下一个检查点（正在做的那一步先做完），页头下面出现一条横幅写明花了多少，你也会收到提示。横幅上的“恢复”让活接着做，并从零重新算起。**改边界**可以改，也可以去掉边界。

- 边界也管着这个事项的子事项。
- 快到边界时（用到 80%），正在干活的 Agent 会被告知这个事项的活会停在那里。
- 同时替别的事项干活的工作组，在这个事项的活停着时，照样做别的事项的活。
- 主助手只照你的话设边界，或者恢复停下的活。

## 改动和撤回

看板下面的**改动**写着这个事项的工作组改过几个文件、其中能放回几个，展开能看到是哪些。**撤回这些改动**先给你预览，确认后把每个文件放回这个事项的活第一次改它之前的样子，子事项的活也算在内。之后又被改过的文件不动，除非你确认覆盖。撤回本身也记下来，所以还能再撤回。详见[行动记录、撤回和急停](./action-log)。

## 结束和重新打开

不再管一件事时，就结束它。为它干的活停在手上那一步，它的触发器也停下。同时替别的事项干活的工作组，接着做别的事项的活。重新打开就从停下的地方接着做：停下的工作组继续，触发器也重新打开，从现在算起（结束期间错过的不补）。

结束不是评判：事项结束以后才交回的交付，照样等你看。已结束的事项会离开侧边栏，在首页勾选“显示已结束”就能找到。你也可以让主助手替你结束一个事项。

## 子事项

工作组可以把自己的一部分活开成一个子事项：这部分有自己的目标和交付，或者你可能想单独跟进它，比如一家店的 Logo。子事项列在它所在事项看板上的同名一栏里，不在侧边栏里；子事项页可以回到它所在的事项。

- 子事项的提问先问开它的工作组。提问卡上写明了这一点；你直接对提问的 Agent 说，也算回答。
- 它的交付交给开它的工作组去用（**交给了开它的工作组**），不等你看。
- 它的花费算进上面每一层事项，上面事项的边界也管着它。
- 结束子事项只停它自己的活；结束上面的事项，它也会一起停下。

“提成顶层事项”会把子事项提到顶层：它会出现在侧边栏和主助手的事项列表里，以后的花费只算它自己的，之前已经花的照旧算在原来的地方。它的提问还是先问开它的工作组。

## 常驻，以及进化事项

触发器开着的事项是常驻的：它的活会按时，或者在有新东西时，自己来。它的节奏卡列出每个触发器，以及下次和上次什么时候触发。主助手会为反复要做的事设好这些，比如每张新订单、新邮件或者每周的报告。详见[触发器和后台常驻](./triggers)。

你让主助手改进空间时，它为此开的事项会在看板上方显示实验室的读数和规矩。详见[进化：实验室和夜间复盘](./evolution)。
