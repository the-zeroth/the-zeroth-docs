**周报**回头看这 7 天：交付了什么、一次过了多少、找了你几次、花了多少，和它自己改了什么。它在侧边栏下面，**自动做事**和**团队与工具**之间。

它只读应用自己的记录：看周报不调用模型，也不告诉任何 Agent，除非你在上面按了验收按钮。它不是处理事情的地方：等你处理的事在对话上方那一条里（见[等你和交付](./needs-you)），此刻谁在做什么看[全景](./panorama)。每天的新消息是主助手的招呼（见[每天的招呼](./main-assistant#每天的招呼)），看周报不算看过它们。

## 算哪几天

周报算的是今天和之前六天，从当地时间零点算起，页面顶上写着，比如**近 7 天 · 11月5日 – 11月11日**。页面上的每个数都算这同样的 7 天。更早的周翻不到。

## 最上面

第一行是这 7 天的大事，比如**交付了 5 件 · 1 件没做成 · 2 个真实对外动作**；都没有时写**没有交付、失败或真实对外动作**。下面是四个数：

| 数 | 是什么 |
| --- | --- |
| **件已交付** | 这 7 天交来的工作，每件事算一次；有没做成的，下面写着**另有 N 件没做成**。 |
| **一次通过** | 第一次交上来你就收下的占多少，比如“验收过的 5 件里 4 件”。只算你自己验收过的；还没有时写**还没有验收过的交付**。 |
| **次找你** | Agent 主动问你的次数，下面写着平均每次交付找了你几次。 |
| **用量** | 这 7 天的花费，下面是 token 数。 |

被找得越少、一次通过越多，说明 Agent 越能自己把活做对。

## 各栏

| 栏目 | 内容 |
| --- | --- |
| **它自己改了什么** | 这 7 天的夜间复盘：几处改动变好且留着、复盘了几次、改了几处；每处改动的读数、改动对比和**撤回**；然后每晚一行，以及复盘员写的修复提案。见[在周报里看和撤回](./evolution#在周报里看和撤回)。 |
| **各个事项** | 每个事项这 7 天交付和没做成的件数，加上它现在的情况（等你回答、一直出错、没有动静、在做）和花了多少。点开看它的看板。 |
| **交付了什么** | 每件事这 7 天里最新的一次交付：目标、属于哪个事项、交付时间、历时和花费，以及交付的 Agent 自己怎么说；**证据包**，**打开事项**（不属于事项的是**打开会话**）。还在等你的带着**接受**、**返工**和**放弃**。先列 8 件，其余的点**再列 N 件**。触发器开的工作标着**触发**。 |
| **没做成** | 这 7 天里最后一次没做成的工作，和交付一样列出。 |
| **撤回不了的动作** | 每件事里真实发生在这台电脑以外的收付款、推送、发邮件、发布和部署。点时间看行动记录里的原始记录；工具给了回执时，还写着服务商、金额、发给几个人、**查看**链接和怎么撤回。测试和彩排只计数，不列出。 |
| **触发** | 你和 Agent 设的触发器这 7 天做了什么，有问题的触发器，以及**管理触发器**（见下面）。 |
| **消息记录** | Agent 的提问、交回和没做成的消息，点**展开**才列出（见下面）。 |

右边是**读数**：

| 读数 | 内容 |
| --- | --- |
| **一次通过了多少** | 一次通过率，近 4 周每周的读数，以及按事项的读数（子事项算在它上面的事项里）。没经你验收就结束的，比如看过未提修改的，另外写明，不算在里面。 |
| **花了多少** | 这 7 天的花费、token 和模型调用次数，有几天就每天一行，以及花得最多的几件事。 |

**它自己改了什么**和**消息记录**总在；别的栏目只在有内容时出现。7 天里记录上什么都没有时，整页只有一句**这 7 天没有可报的事**。

## 触发

**触发**说的是你和 Agent 设的触发器：一共触发了几次、开了几个新任务、叫醒 Agent 几次、跳过和补跑了几次，每个触发器最近一次是什么时候，它们开的任务现在怎样，以及下一次是什么时候、哪一个。错过的时间补跑过才写**补跑 N 次（错过 M 次）**；一次也没补跑时写**错过 M 次，没有补跑**。所有触发器都暂停着时，这里会写明。

有问题的触发器分两组：

- **现在还有 N 个问题没解决**：看不了的来源、开不了的 Webhook 入口，点**查看触发器**去修。
- **这 7 天里有 N 个触发器没送到过**：这几天里有一次没能开任务、叫醒 Agent 或交给主助手；之后也许已经送到了。

应用自带的**夜间复盘**不在这一栏：它这一周做了什么，在**它自己改了什么**里。所以只有夜间复盘、没有别的触发器时，周报里没有这一栏；夜间复盘没能开始时，会列在有问题的触发器里。触发器本身见[触发器和后台常驻](./triggers)。

## 消息记录

**消息记录**的标题下面是这 7 天的读数，比如“近 7 天：5 次提问 · 12 次交付 · 1 次失败 · 每次交付被问 0.4 次”。点**展开**列出消息：先是所有还开着的，不管多早来的；再是这 7 天里处理过的。两组都是新的在前。对话上方那一条里已经有卡片的，不在这里再列一遍，在卡片上处理。

每条消息开头写着它是**提问**、**交回**还是**没做成**，接着是哪个 Agent 或哪次运行、什么时候来的、属于哪个事项（点**事项：…**打开那个事项的看板）。还开着的提问可以直接在这里回答；提问上标着**它边等边继续做**的，说明 Agent 没有停下来等你。交付写着它现在怎样，带着**证据包**，最新的一次还带着验收按钮。**打开**回到它来自的那段对话。

不打算回答的问题点**收起**（如果 Agent 是用卡片问的，它会知道卡片被取消了）；看过的交付或失败点**标为已读**。处理过的消息写着怎么结束的：**已回答**、**已查看**、**已收起**、**已结束，未回答**或**已被更新的结果替换**。处理过的只列最近的一部分，列不全时会写明。

## 还要知道

- 周报属于当前空间，和等你的事、事项、触发器一样。只有花费是这台电脑上所有空间的合计，页面上会写明。
- 你结束了的事项，周报里也不再等你：它这 7 天交来的交付照样算进交付了几件，在**交付了什么**里写着**事项已结束，重新打开后再验收**，不带验收按钮。重新打开事项，验收按钮就回来。
- 从主助手的招呼里点**看这些对外动作**，或者在对话上方那一行**撤回不了的对外动作**上点**在周报里看**，都会打开周报的**撤回不了的动作**。
