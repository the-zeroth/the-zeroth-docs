**A-Genetic Engineering（Agent 基因工程）** 是对 The One 中“一支多 Agent 团队如何被写下来”的命名：完整地写成定义空间里的文件，可以复用、修改、传给别人。[Prolifera Engineering（增殖式工程）](../prolifera-engineering)描述系统在工作中如何**长出来**；A-Genetic Engineering 描述它依照**什么**长。A 即 Agent：Agent-Genetic 的缩写。

## 两个半成品

上一代 Agent 产品，各自握着答案的一半：

- Claude Code、Codex 这类单体 Agent 用 Skill 沉淀经过验证的经验与流程。这是**经验**，但没有结构承载它——一份 Skill 在新对话里落进怎样的上下文、被怎样的角色执行，每次都不一样，于是经验会漂移。
- 它们的 Multi-Agent 则是临时生成的 sub-agent：干完杂活即被丢弃。这是**结构**，但没有遗传——再合理的分工，跑完一次就消散，下一次从零来过。

经验没有结构，就会漂移；结构没有遗传，就会消散。

## 基因型：空间里写下了什么

在 The One 中，一支团队被**完整地**写进一个[定义空间](../../the-one-app/capabilities/definition-spaces)，每一部分都能在**能力**里找到：

- **工作组模板**（`workflows/*.yaml`，也就是 Graph）——节点与边。每个节点绑定一个角色，还可以只为这个节点追加指令；每条边的文字就是移交指令本身：何时移交、交出什么、期待对方产出什么。这是团队的**身体蓝图**。
- **角色**（`agents/*.yaml`，也就是 Agent 预设）——每个成员的指令、所用的模型预设（或默认模型）、推理设置、内置工具与 MCP server、技能、提示词和插件，彼此独立定义。这是每一种**细胞类型**。
- **技能**与**提示词**——写下来的做法和共用的说明，挂到需要它们的角色上。
- **插件引用**——角色可以写明自己用哪些插件。空间里只记引用；插件本身装在每台电脑上，不属于任何一个空间。
- **记忆**——空间设计背后的理由和学到的教训，由 Agent 和夜间复盘写下。每一轮，持有记忆工具的 Agent 会看到和最近的消息最相关的条目，最多 20 条。见[记忆与召回](../../the-one-app/capabilities/memory)。

单独看，这些上一代都有雏形。融合才是关键：当经验式的 Skill 落进一个**固定位置**——指令明确、工具明确、在团队里的位置明确、移交的边也明确的角色——而不是随便哪段碰巧加载了它的对话，经验才第一次停止漂移；当结构连同每个成员的全部配置被写成文件，而不是散在一次运行的内存里，结构才第一次可以遗传。一支真正可复用的成熟团队，是这两者的融合体——这份完整的记录，就是它的**基因**。

## 表现型：事项上的工作组

于是基因型与表现型分开了。模板是基因型。**主助手**把一个**事项**的活交给某个模板时，The One 为它开一次新的运行：一个**工作组**，也就是表现型，在这个事项的看板上干活。一个模板可以同时为几个事项干活；能力页的**正在为事项干活的模板**列着它们。

表达还可以在工作组内部继续：Agent 用 `create_subgraph` 把另一个模板拉起为本组的子 Graph，还可以把这部分活开成一个有自己看板的子事项。工作组会睡下、暂停、结束；基因留下来，下一次表达时结构与配置逐字复现。（忠实指的是复现配置，不是复现行为——模型的输出仍是随机的，同一份基因不保证两次运行一字不差。）

环境可以变，基因不必跟着变。主助手可以只为这一次派活给工作组换用别的模型；而把模型预设绑到角色或模板上，会改变以后的每一次运行，只在确实要这样时才做。

## 主助手是基因工程师

这些复杂性不需要由你承担。你所在空间的[主助手](../../the-one-app/main-assistant)决定表达哪份基因、什么时候该改：

- **选择**：每个事项，它从空间的模板里挑合适的那个（每个模板是做什么的，就列在它的上下文里），几个都合适时，优先选做过这类活、做得好的。
- **编写**：没有合适的模板、而这类活还会再来时，它会安排写一个新的：把编写交给 `atlas` 工作组，或者自己用 definition-authoring 技能改定义。
- **观察**：每份交付它都对照你最初的要求检查；工作组的提问它能答就答，该你定的留给你；工作组停住了它会知道。交付的评判始终在你：**接受**、**返工**或**放弃**。
- **定向进化**：你让空间把自己的活做得更好时，它开进化事项（见下文）。

底下的编辑台对每个 Agent 都一样：按确切的修订号读取整个空间，组成一批改动，可以先试运行（dry-run），并对照 schema、定义之间的引用、工具与 MCP 的绑定和插件是否可用来校验，再作为一次改动提交。Agent 的每次修改都记在**行动记录**里，可以撤回。能力里的各个编辑页和[总图](../../the-one-app/capabilities/atlas)改的也是同一批文件。

## 定向进化

由证据驱动的基因编辑，就是**定向进化**。The One 在每个空间里跑两条这样的回路：

- **进化事项**：你请主助手改进这个空间，它开一个名为 Evolution 的事项，交给实验室工作组：总监、改动员、验证员。每一轮先普查真实的失败，最多试一个假设，门槛在第一次读数之前就写好；只改出问题的最小一层，过了这道门槛才上线；旧版冻结成副本，变差了可以撤回。每周一次的普查让这件事接着推进，没有新情况的那周会跳过。
- **夜间复盘**：每天夜里 03:30，真实使用中出现了新的摩擦，复盘员就把反复出现的问题写成记忆里的一条教训，或者改进一个技能，一晚最多三处。每处改动都按它针对的摩擦对比前后；变差了或到期没见效的，由复盘员撤回或改进；每处改动你都能在晨报里看到，也能在那里撤回。

[Self-Evolution（自我进化）](../more-possibilities/self-evolution)讲这两条回路背后的想法；[进化：实验室和夜间复盘](../../the-one-app/evolution)讲在应用里怎么开始、怎么跟进。

## 遗传

基因的意义在于传承。一个空间可以复制、导出、导入和分享（`.zerospace`），它的定义都会一起走：

- **记忆**走不走由你定：导出默认带上 agent 记忆，可以取消勾选；分享默认不带，要勾选**包含 agent 记忆**才带。
- **插件**以引用的形式随行，由收到空间的那台电脑另行安装。
- **密钥**从不随行。
- **模型**也留在各自的电脑上：角色写的是模型预设，而预设保存在应用里，所以从别处来的空间，可能要把角色改到你自己的预设上。

官方空间是只读的基因组基线：在里面，主助手和进化实验室找到的改进只能留作提议。把它复制成你自己的空间，就能培育自己的变体；官方空间以后的更新不会自动进到副本里。见[定义空间](../../the-one-app/capabilities/definition-spaces)。

## 边界

这个类比和 Prolifera 一样，借自生物学，用作描述机制的朴素词汇，并非宣称 Agent 拥有生命。几条值得直说的边界：

- **宿主不会自己改基因。** 除了给空间补上缺少的内置定义（只补不覆盖），每一次定义改动都是某个 Agent 或你的决定。夜间复盘在后台运行，但改什么由复盘员决定，和其他改动一样被记录、被衡量、可以撤回。
- **基因不保证表现。** 它固定的是结构、配置与经验落点，消除的是两次表达之间的漂移；单次运行的质量仍取决于模型本身。
- **改了不等于改好了。** 改动有没有用，要靠读数来定：实验室事先写好的门槛、夜间复盘的前后对比，或者再跑一次看看——而不是默认相信。
