title: 上下文与冥想
description: Agent 的上下文分约束、信息、任务三类；The One 把它分成几块交给模型，快满时由 Agent 冥想，原地压缩自己的历史。
---

上下文可以按作用分为三类，对应人类的哲学三问——**我是谁？从哪里来？到哪里去？**

1. **约束（我是谁？）**：在提示词里告诉 Agent 它是什么身份，擅长做什么，职责是什么，怎样做才算做对。
2. **信息（从哪里来？）**：和任务有关的有效信息，比如代码仓库里已有的代码和文档。
3. **任务（到哪里去？）**：要它去做的事。

要评判一个 Agent 上下文的好坏，根本在于以上三点是否完整、明确、清晰，以及与这三点无关的冗余上下文是否已尽可能剔除。

## Agent 看到的是什么

一个 Agent 每次请求模型时，带着这样几块：

- **系统提示**：它的角色写下的指令，加上它在工作组里的位置：能把工作交给谁，什么时候交。
- **技能和文件**：起初折着，只露名字和简介；用到时展开，用完折回。
- **记忆卡**：持有记忆工具的 Agent，每一轮会看到空间记忆里和最近的消息最相关的条目，最多 20 条。见[记忆与召回](../../the-one-app/capabilities/memory)。
- **计划**：它用计划工具写下的行动计划，见 [ReAct 与回合](./react)。
- **历史**：到目前为止的对话、工具调用和结果。

这几块在工作中会变：技能展开了，记忆卡换了，计划更新了。The One 不会每一轮都把它们从头重写一遍，而是把一段时间里不变的部分固定下来，叫一个**纪元**；纪元里的变化作为一条“上下文更新”追加在历史末尾。模型服务因此能复用已经读过的开头，不必每一轮都按全价重读整段对话。

换了模型或工具、冥想了，或者追加的更新攒得太多时，就开一个新纪元，把当前的样子重新写成新的开头。从一个 Agent 克隆出来的 Agent 接着它的纪元，第一次请求就能复用原来那份。在[所有运行](../../the-one-app/settings/all-runs)里查看一个 Agent 时，**上下文模式**可以在纪元和经典之间切换，**发送视图**显示下一次请求发给模型时的完整样子。

## 冥想：快满时自己压缩

上下文窗口是 Agent 能连续工作多久的硬上限。每个 Agent 都带着 `meditate` 工具，可以“冥想”：由一个继承它的模型和思考设置的 summarizer 原地压缩它的对话历史，让它带着一份更小、更干净的上下文接着做。

- **自己决定**：Agent 可以随时冥想。在那之前很久，它的历史一越过 6 万、10 万、15 万 token（之后每多 5 万），你下一次给它发消息时，它就先收到一条提示，告诉它上下文有多大；压不压由它决定。它也可以在交回时带上 `meditate_after=true`，等这一轮结束、你在读它的回答时再压缩。
- **快满时自动开始**：真实的上下文用到模型工作窗口的 85% 时，冥想会自动开始。长时间运行的 Agent 因此在溢出之前就把自己缩下来，而不是在上限处卡住。
- **记忆比压缩活得久**：summarizer 只负责压缩，不能写记忆。持有记忆工具的 Agent 可以在冥想之前用 `remember` 把一条教训留进空间的记忆，让长任务留下知识，而不是被压缩一笔勾销。
- **看得见**：每一次冥想都记在消息时间线里，你能看到 Agent 在哪里压缩了自己。

冥想不是“分裂”：上下文过载的 Agent 不会因此变成几个 Agent。Agent 怎样变成几个，见 [Prolifera Engineering（增殖式工程）](../prolifera-engineering)。
