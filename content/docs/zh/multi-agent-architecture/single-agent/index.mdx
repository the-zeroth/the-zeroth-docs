title: 单一 Agent
description: 一个 Agent 由模型、工具和上下文三样东西决定；在 The One 里，角色就是把这三样写下来的 Agent。
---

本质上，每个 Agent 由三样东西决定：

1. **模型**：Agent 的大脑。
2. **工具**：Agent 的手脚。
3. **上下文**：Agent 的心智，包括系统提示、技能、记忆，以及到目前为止的全部对话。

一切上下文都会影响模型的判断，不仅仅是系统提示。

## 模型

在近几年火热的模型竞赛中，我们可以发现一个事实：完美的模型尚未出现，最强的几个模型之间没有绝对的强弱，而是各有优劣，各有擅长。

所以在 The One 里，每个角色可以选一套保存好的模型预设（模型连同它的连接、思考强度和速度），或者跟随默认模型，让工作组里的每个成员都用适合自己那部分活的模型。见[模型](../../the-one-app/capabilities/models)。

## 工具

Tool 让一个 LLM 真正成为 Agent。没有 Tool 的模型再强大，也只是一个聊天机器人；Tool 的边界就是 Agent 能力的边界。

这个边界不是在 Agent 建好时就固定死的。每个 Agent 都自带三组管理自己的工具：

- **能力管理**（Capability Manager）：在工作中给自己找技能并装上（也可以扫描别人的技能仓库），把应用里已经配好的 MCP 服务器接到自己身上，按需取出只露了名字的工具的完整参数。
- **上下文控制**：技能和文件起初是折起来的，只露出名字和简介；用到时展开，用完折回去。
- **冥想**（`meditate`）：压缩自己的历史，见[上下文与冥想](./context)。

除此之外，一个 Agent 有哪些工具由它的角色决定：内置工具（读写文件、运行命令、访问网络、创建 Agent 和子 Graph……）、MCP 服务器和插件。工具说明的是 Agent **能**做什么，不是它**被允许**做什么：The One 里没有什么会拦下一次调用，安全靠记录和撤回，见[没有审批这一步](../record-and-undo)。

能力也可以打包。一个**插件**可以把技能、脚本、MCP 服务器、应用和连接装在一起；把它加给一个角色，这个角色就拿到插件带来的能力，而定义空间里只记着对它的引用。持有插件制作工具的 Agent 也可以自己做一个插件，再把它加给某个角色。见[插件与应用](../../the-one-app/capabilities/plugins)。

## 角色：写下来的 Agent

在 The One 里，这三样东西写在一个**角色**里：用哪套模型预设，读哪些提示词和技能，带哪些内置工具、MCP 服务器和插件。工作组模板里的每个节点绑定一个角色，所以同一个角色可以出现在很多工作组里；改一处，以后每一次都照新的来。见[角色](../../the-one-app/capabilities/roles)。
